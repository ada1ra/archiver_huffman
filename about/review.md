# 1. Обзор задания: Архиватор на базе алгоритма Хаффмана

- **Автор:** Разгуляева Ада Игоревна
- **Группа:** 25.Б42-мм
- **Научный руководитель:** Юрий Викторович Литвинов
- **Тема:** Консольный архиватор с использованием алгоритма Хаффмана для сжатия и восстановления файлов.

---

### 1.1. Цель работы

Разработать консольное приложение для сжатия и восстановления файлов на базе алгоритма Хаффмана, а также оценить эффективность алгоритма в зависимости от типа и размера данных, включая измерение степени сжатия и производительности.

---

### 1.2. Теория

Алгоритм Хаффмана — это метод сжатия без потерь, который использует префиксный код для представления символов.

#### 1.2.1. Префиксные коды

Ключевая идея алгоритма: часто встречающимся символам присваиваются короткие коды, а редким — более длинные. При этом используется **префиксный код** — ни одно кодовое слово не является началом другого. Это свойство позволяет однозначно декодировать сообщение без разделителей.

#### 1.2.2. Принцип работы

1. **Подсчёт частот**: анализируется входной файл для определения частоты каждого символа.
2. **Построение дерева**: из символов создаются узлы-листья, которые помещаются в приоритетную очередь. Затем многократно извлекаются два узла с наименьшей частотой, объединяются в новый узел (с суммой частот), который возвращается в очередь. Процесс повторяется до тех пор, пока не останется один узел — корень дерева.
3. **Генерация кодов**: при обходе дерева от корня каждому левому переходу соответствует 0, правому — 1.
4. **Кодирование**: исходные символы заменяются на битовые последовательности в соответствии со сгенерированной таблицей кодов.

#### 1.2.3. Теоретическая оптимальность

Алгоритм Хаффмана находит дерево с минимальной взвешенной внешней длиной пути. Он доказуемо оптимален среди кодов, использующих целое число битов на символ, в отличие от алгоритма Шеннона-Фано, который может давать субоптимальные результаты.

#### 1.2.4. Где используется на практике

- **ZIP, GZIP, RAR**: алгоритм Хаффмана применяется как финальный этап сжатия.
- **JPEG, PNG, MP3**: используется для сжатия коэффициентов после преобразований.
- **PDF, HTTP-запросы**: DEFLATE с кодированием Хаффмана используется для сжатия потоков данных.

---

### 1.3. Примерная функциональность

Программа должна поддерживать два режима через интерфейс командной строки:

- **Сжатие**:
    - Подсчёт частот символов входного файла (анализ всех байтов от 0 до 255).
    - Построение дерева Хаффмана с использованием приоритетной очереди.
    - Генерация префиксных кодов для каждого символа.
    - Запись заголовка в выходной файл: исходный размер (8 байт), количество уникальных символов (2 байта), затем для каждого символа — сам байт (1 байт) и его частота (8 байт).
    - Кодирование данных: замена исходных байтов битовыми последовательностями с буферизацией до 8 бит.

- **Разжатие**:
    - Чтение и разбор заголовка для восстановления частот символов.
    - Восстановление дерева Хаффмана.
    - Побитовое чтение закодированного потока и обход дерева до достижения листа.
    - Вывод восстановленного символа в выходной файл.

### 1.4. Технические реализации алгоритма

#### 1.4.1. Открытые реализации на C

- **SmnTin/huffman-archiver**: архиватор с каноническими кодами Хаффмана, оптимизированный для больших файлов. Пропускная способность сжатия — ~195 MB/s, разжатия — ~90 MB/s на MacBook Pro с M2 Pro.
- **MichaelDipperstein/huffman**: простая и читаемая ANSI C реализация, включающая как классические, так и канонические коды Хаффмана.
- **ConnorDye/C-Zip**: учебный проект на C с модулями для работы с битами, списками и деревьями.

#### 1.4.2. Реализации на других языках

- **C++**: проекты Suddhu018 (с использованием priority_queue, unordered_map, рекурсии) и другие реализации с поддержкой всех типов файлов.
- **Python**: реализации с библиотекой heapq и подробными примерами, а также проекты с графическим интерфейсом на Tkinter.
- **Кроссплатформенные решения**: коллекции алгоритмов сжатия на C++, Rust и Python.

---

### 1.5. Ожидаемые результаты исследования

На основе анализа открытых реализаций и экспериментальных данных ожидаются следующие результаты:

- **Текстовые файлы** (русский/английский язык, однобайтовая кодировка): сжатие на 40–55%.
- **Разжатие работает быстрее сжатия**: декодирование — прямой обход дерева по битам, в то время как кодирование требует построения дерева и таблицы кодов.
- **Для очень маленьких файлов** (менее нескольких килобайт) или случайных/уже сжатых данных сжатие неэффективно: размер может увеличиваться из-за оверхеда заголовка с частотами символов и округления битового потока.
- **Хаффман против Шеннона-Фано**: оба алгоритма дают схожую среднюю длину кода и степень сжатия, но Хаффман требует меньше времени на выполнение благодаря более простой процедуре построения дерева.

---

### 1.6. Критерии успешной работы

- Программа корректно восстанавливает исходный файл после сжатия (проверяется утилитой `diff`).
- Получены измеримые результаты: степень сжатия (коэффициент = сжатый_размер / исходный_размер) и производительность (время сжатия и разжатия в секундах).
- Проведён анализ эффективности на различных типах данных: текстовые файлы, бинарные файлы (исполняемые, изображения), уже сжатые файлы (ZIP, JPEG).
- Выявлены сценарии, где алгоритм эффективен (текстовые данные, низкая энтропия), и сценарии, где сжатие нецелесообразно (малые файлы, случайные данные).
